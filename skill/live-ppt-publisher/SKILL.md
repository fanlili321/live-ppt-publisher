# 直播PPT定稿发布

只处理已经定稿并导出的成品。禁止打开、修改或重新导出 `.key`；禁止进入 PPT 制作、复核或内容改写流程。

## 固定交付结果

每期交付必须同时满足：

1. 飞书共享文件夹包含 `.key`、PDF、逐页图片子文件夹。
2. 腾讯文档为普通在线文档，统一存放在腾讯文档的“直播”文件夹下，正文按顺序插入全部 PPT 图片；不要直接把 PDF 作为对外版本。
3. 腾讯文档权限为“所有人可查看”。
4. 通过飞书私聊把飞书共享文件夹链接和腾讯文档链接发给用户本人。
5. 用户确认两个链接无误后，将飞书共享文件夹链接发送到课程群并艾特王磊，将腾讯文档链接发送到渠道群并艾特胡亮。
6. 在直播后的第二个A股交易日，将该期PDF的飞书文件直链发送到渠道群并真实艾特胡亮；发送前必须向用户展示预览并取得确认。

## 输入识别

默认从 `~/Downloads` 查找本期待发布文件，也接受用户指定目录。

- 识别同一标题的 `.key`、`.pdf` 和逐页图片。
- 图片名必须含稳定页码，如 `.001.jpeg`、`.002.jpeg`；按数字页码排序，不按文件系统返回顺序排序。
- 用 PDF 页数与图片数量交叉核对。数量不一致时停止发布并报告差异。
- 从文件名或飞书资料核对期数和 PPT 标题；禁止把 `XX` 当作字面期数。
- 若候选有多套或标题无法唯一对应，列出候选并请用户确认。

## 第一步：飞书归档

使用 `lark-drive`，以 user 身份操作。

1. 读取用户指定的飞书共享父文件夹；未提供且无法从明确配置定位时，先询问，禁止把某一期示例文件夹当作父目录。
2. 参考历史格式创建本期子文件夹：`第{期数}期-{PPT标题}`。
3. 在本期文件夹根目录上传：
   - `{PPT标题}.key`
   - `{PPT标题}.pdf`
4. 在本期文件夹内创建图片子文件夹：`{PPT标题}`。
5. 将全部逐页图片上传到图片子文件夹，保留三位页码后缀。
6. 重新列取文件夹，核对 `.key`、PDF、图片数量、页码连续性及文件名。
7. 返回本期飞书共享文件夹链接，不要返回单个文件链接作为归档链接。

历史命名示例：

- 本期文件夹：`第473期-社保基金，是如何获得7%-8%的年化的？`
- 图片子文件夹：`社保基金，是如何获得7%-8%的年化的？`
- 图片：`社保基金，是如何获得7%-8%的年化的？.001.jpeg` 至 `.023.jpeg`

## 第二步：腾讯图片文档

腾讯文档没有可用的专用连接器时，使用 `browser:control-in-app-browser`，并先完成其工具发现与浏览器初始化要求。

1. 登录腾讯文档，在云盘中唯一定位名为“直播”的文件夹并进入。若存在多个同名文件夹，展示路径并请用户确认；若文件夹不存在，暂停并请用户确认是否新建，禁止把文档放在根目录代替。
2. 必须在“直播”文件夹内新建普通“文档”，不要新建幻灯片，也不要把 PDF 作为最终对外文档。
3. 标题使用：`第{期数}期螺丝钉专属直播课-{PPT标题}`。
4. 将逐页图片按页码逐张上传：每张完成插入后再选择下一张。禁止一次多选或并发上传；腾讯文档可能按完成时间落位，导致页序错乱。
5. 每张图片插入后新建下一段，使图片独占一段，避免并排、乱序、裁切或漏页。
6. 核对首图、末图、图片总数和至少一个中间页。
7. 打开分享设置，将权限改为“所有人可查看”；这是权限变更，必须在执行时遵守浏览器的确认规则。
8. 复制并验证腾讯文档链接；用权限状态确认外部查看设置已生效，并返回文件列表核验该文档确实位于“直播”文件夹下。

## 更新既有期数

需要修改某一页时，打开原腾讯图片文档并替换对应图片，保持原文档和原链接；不要重新新建文档。替换后再次核对页序和公开查看权限。

飞书侧按用户指定策略处理：默认覆盖本期文件夹中同名 `.key`、PDF和对应页图片，避免制造重复版本；覆盖、删除或冲突处理属于高风险写操作，必须先展示目标和取得明确确认。

## 第三步：飞书回传

使用 `lark-contact` 唯一解析用户本人，再使用 `lark-im` 私聊。发送属于代表用户的外部通信，必须在真正发送前展示最终文本并取得确认。

建议消息格式：

```text
第{期数}期直播PPT已发布：

飞书共享文件夹：{feishu_folder_url}
腾讯在线文档：{tencent_doc_url}
```

发送后记录 `message_id`，并在最终回复中给出两个链接和发送结果。

## 第四步：课程群与渠道群通知

完成私聊回传后必须暂停，等待用户明确确认两个链接无误。未收到该确认时，禁止向课程群或渠道群发送消息。

1. 使用 `lark-im` 搜索并唯一定位课程群和渠道群；如果任一群出现多个候选，列出群名和 `chat_id` 请用户选择，禁止擅自选取。
2. 使用 `lark-contact` 唯一解析王磊和胡亮的 `open_id`，在消息中使用真实飞书艾特标签；禁止只输入纯文本姓名冒充艾特。出现同名候选时请用户选择。
3. 在请求链接确认时，同时展示两个群名、两位艾特对象和两条待发送的完整文本。用户确认链接无误并同意发送后，再以“直播小助手”身份分别发群消息；禁止使用范丽丽个人身份发送。
4. 发送前读取并校验当前发送者身份，只有明确显示为“直播小助手”才可继续；若无法切换或无法确认身份，立即暂停并报告，禁止退回个人身份代发。
5. 课程群只发送飞书共享文件夹链接，不发送腾讯文档链接。固定话术为：

```text
第{期数}期直播ppt已上传，请知悉
{feishu_folder_url}
@王磊
```

6. 渠道群只发送腾讯文档链接，不发送飞书共享文件夹链接。固定话术为：

```text
第{期数}期直播ppt腾讯文档已生成，请知悉
{tencent_doc_url}
@胡亮
```

7. 发送后分别记录课程群、渠道群的 `chat_id`、发送者身份和群消息 `message_id`，并在最终回复中报告两个发送结果。

## 第五步：第二个交易日发送PDF

1. 从已确认的直播物料、群消息或直播信息中核对实际直播日期，禁止用文件上传时间代替。若直播日期无法唯一确认，先询问用户。
2. 使用可靠的A股交易日历计算直播日之后的第二个交易日：不计直播当天，跳过周末、法定休市日和临时休市日。禁止简单按两个自然日计算。
3. 在本期飞书共享文件夹根目录唯一定位 `.pdf` 文件，读取并使用PDF文件本身的飞书直链；禁止使用共享文件夹链接或腾讯文档链接代替。
4. 唯一定位渠道群与胡亮，使用真实飞书艾特。发送身份必须为“直播小助手”，并遵守第四步的身份校验规则。
5. 在创建定时任务或发送消息前，向用户展示确认窗口，至少包含：期数、直播日期、第二个交易日、计划发送时间、渠道群、艾特对象、发送身份、PDF文件名、PDF直链和完整话术。未得到明确确认时，禁止落地。
6. 固定话术为：

```text
{期数}期直播ppt如下，辛苦请雪球合规审核
{feishu_pdf_url}
@胡亮
```

7. 用户确认后，为第二个交易日的约定时间创建一次性执行安排；到点发送前再次校验PDF链接、渠道群、胡亮和“直播小助手”身份。若确认时已经处于目标交易日，则按用户确认的具体时间发送。
8. 发送后记录直播日期、目标交易日、实际发送时间、渠道群 `chat_id`、发送者身份和 `message_id`，避免重复发送。

## 完成检查

只有以下项目全部通过才可声明完成：

- 本地三种成品唯一匹配。
- 飞书本期文件夹命名正确，三类文件齐全。
- 腾讯文档图片数量与 PDF 页数一致且顺序正确。
- 腾讯文档位于腾讯文档的“直播”文件夹下，不在根目录或其他文件夹。
- 腾讯文档标题正确、权限为“所有人可查看”。
- 两个链接已通过飞书私聊发给正确用户，且有发送结果或 `message_id`。
- 用户已明确确认两个链接无误。
- 两条群通知的发送者身份均已校验为“直播小助手”，且不是范丽丽个人身份。
- 飞书共享文件夹链接已按固定话术发到唯一确认的课程群，并真实艾特王磊，且有群消息 `message_id`。
- 腾讯文档链接已按固定话术发到唯一确认的渠道群，并真实艾特胡亮，且有群消息 `message_id`。
- 第二个交易日的PDF通知已在用户确认后安排或发送；目标日期按A股交易日历核验，链接为PDF文件直链，渠道群、胡亮艾特和“直播小助手”身份均正确，并留有任务或消息记录。

任何一步失败都保留已完成结果，报告准确位置和可继续执行的下一步；不要重新制作 PPT。
